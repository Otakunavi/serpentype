# Локальный стенд совместимости PDF в КК

Стенд воспроизводит HTML-пайплайн уведомления № 7 на dev (`4ea5b32d`) на синтетических данных RU и KK. Он передаёт одинаковую HTML-строку обоим движкам. В ней сохранены редакторская разметка верхнего QR, CSS-подложка, колонтитулы, порядок QR и приложений, а также альбомная ориентация приложения 2.

## Запуск

Из каталога `pdfpipe` с Python 3.10 или новее:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python render.py --renderer both --mode both
```

WeasyPrint также использует системную библиотеку Pango. Если она установлена через Homebrew на Apple Silicon и Python её не находит, добавьте `/opt/homebrew/lib` в `DYLD_FALLBACK_LIBRARY_PATH`.

Запуск без параметров повторяет dev для черновика на Serpentype. `--mode signed` воспроизводит рендер после подписания XML с тестовыми ссылками на PDF и XML. Результаты лежат в `output/<режим>/<движок>/`. В консоль выводится число страниц каждого PDF.

Шрифты берутся из локального профиля с Noto Sans. Чтобы сравнить с конкретным стендом по переносам и метрикам, передайте его локальную копию `fonts.css` через `--fonts-css`. Пути к шрифтам в ней должны вести к локальным файлам. После установки зависимостей рендеринг работает офлайн.

## Проверка кандидата 0.11.0

Для проверки локальной сборки установите пакет из корня репозитория и запустите тест.

```sh
python3 -m pip install '.[test-pdfpipe]'
python3 -I -m unittest discover -s tests -p 'test_pdfpipe.py' -v
```

Тест сверяет обе подложки, черновые SVG-заглушки, страницы приложений,
колонтитулы и положение QR. ZXing считывает ссылки из растра подписанного PDF.
Стенд передаёт исходные MIME из dev. Совместимость с `image/svg` и SVG,
объявленным как `image/png`, обеспечивает загрузчик изображений Serpentype.
Отдельный тест сверяет оба варианта с обычным `image/svg+xml`.

Эти режимы используют текущую подстановку dev и прямой результат движка. Замеры сделаны с локальным профилем шрифтов.
