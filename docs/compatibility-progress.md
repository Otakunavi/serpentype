# Compatibility verification (0.6.0)

The current development build fixes vertical line drift caused by nested inline elements with smaller font sizes, preserves inherited unitless `line-height` on headings, paints positioned content in stacking order, centers images according to inherited text alignment, centers collapsed outer-table borders on their grid edges, and draws winning collapsed borders at page-fragment boundaries. CSS passed beside the HTML now has user stylesheet priority, below normal declarations embedded in the document. In the WeasyPrint-shaped API, deeply nested inline runs also use the font's vertical bounding box when sizing line boxes; ordinary `Renderer` output and table-cell line sizing are unchanged.

The supplied 0.2.1 fixture pack was re-run with its unmodified HTML using four spawned workers and WeasyPrint 64.1. Both the default page-limit run and the `max_pages=1000` run completed all 19 fixtures. Across all 353 pages there are no Serpentype diagnostics, overflow, missing glyphs or unsupported-feature reports. Page counts and orientation match, including the 2000-row table at 251 pages in each renderer. MediaBox sides differ by at most 0.0045 pt.

All extracted words occur on the same pages. One page has an inferred-space difference before a colon in PDF text extraction; the glyph runs meet at the same x-coordinate and the HTML contains no space before the colon. At 72 dpi, mean absolute grayscale pixel error is 1.3098 on a 0–255 scale; none of the 353 page images is pixel-identical. The registration appendix's second data row starts on page 3 in both engines. These results establish compatibility for the fixture pack's required checks, but do not establish pixel-identical output or complete WeasyPrint compatibility.
